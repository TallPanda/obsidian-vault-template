# Session Log

## Purpose

Create or update a session log for the current conversation. Run at session wrap-up (with user confirmation) or on demand.

## Steps

### 1. Read marker files

```bash
cat ~/.claude/current-session-marker 2>/dev/null
cat ~/.claude/current-session-log-stem 2>/dev/null
```

- If `current-session-marker` is empty or missing → **new session**, continue to Step 2
- If `current-session-marker` has a UUID → **existing session**, skip to Step 4

### 2. Generate UUID (new session only)

```bash
uuidgen 2>/dev/null || python3 -c "import uuid; print(uuid.uuid4())"
```

Note the UUID — you will write it to the marker file in Step 3.

### 3. Generate filename (new session only)

Summarise the conversation into a short kebab-case slug (e.g. `fermentation-guide`, `meal-planning-setup`). Form the stem:

```
YYYY-MM-DD-<slug>
```

Use today's date. Write the UUID and stem:

```bash
echo "<uuid>" > ~/.claude/current-session-marker
echo "YYYY-MM-DD-<slug>" > ~/.claude/current-session-log-stem
```

### 4. Archive old logs

Move any log files in `<VAULT_ROOT>/1 - Inbox/Logs/` older than 24 hours to `<VAULT_ROOT>/1 - Inbox/Logs/Old/`. Skip the current session's log file.

### 5. Create or update log

Read `~/.claude/current-session-log-stem` to get the stem. The log path is:

```
<VAULT_ROOT>/1 - Inbox/Logs/<stem>-session.md
```

**New log:** If the file does not exist, copy the template from `<VAULT_ROOT>/0 - Meta/Templates/session-log.md`. Substitute `{{date}}` with today's date (YYYY-MM-DD) and `{{time}}` with the current time (HH:MM). Fill all sections from conversation context.

**Existing log:** Read the file and update relevant sections in place. Do not overwrite sections that already have content unless updating them.

### 6. Topic drift check

Compare the current conversation topic against the stored stem. If the topic has shifted significantly, propose a rename:

> "The conversation has moved to [new topic]. Want me to rename the log from `<old-stem>` to `<new-stem>`?"

On confirmation: rename the file, update `current-session-log-stem`. On decline: keep existing name.

## Notes / Gotchas

- `current-session-marker` stores a UUID generated by this skill — not a JSONL session ID. Each invocation in a new session writes a new UUID.
- Two simultaneous sessions share the same marker files; the second to invoke will overwrite the first. This is a known edge case for rapid parallel usage — for normal use it is not an issue.
- `uuidgen` is available on most Linux/macOS systems. The `python3` fallback covers cases where it is not.
- Replace `<VAULT_ROOT>` with the absolute path to your vault root.
